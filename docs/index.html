Set up your workout feed

Workout Feed reads a small JSON file — the manifest — from a URL you control, downloads the workout files it lists, and schedules them into the Workout app on your Apple Watch. This guide takes you from nothing to a working feed in about five minutes.

How it works

Your host→ index.json + .workout files→ Workout Feed→ Apple Watch

A feed is just two kinds of static files:

  • One manifest (conventionally index.json) listing your planned workouts — what, when, and where the file for each one lives.
  • One or more .workout files — Apple's binary workout-plan format, the same thing you get from Share Workout on the watch.

Anything that can serve those over HTTP is a valid feed: GitHub Pages, S3, nginx, a Raspberry Pi on your shelf. The app polls the manifest — on launch, on pull-to-refresh, and in the background — and keeps the watch schedule in sync with it. You never touch the watch.

The app asks for two things:

  • Feed URL — the manifest's URL. That's the only required field.
  • Authorization — only if your host requires it. Most setups don't; skip it unless you know you need it.

Quick start — a feed in 5 minutes

The simplest possible feed is two files on GitHub Pages. The same steps work on any static host.

1. Make a .workout file

The quickest scripted path is @bibixx/workoutkit, a TypeScript SDK for Apple's .workout format (no Apple account needed):

mkdir my-feed && cd my-feed
npm install @bibixx/workoutkit

Save this as make-workout.mjs and run it with node make-workout.mjs:

import { WorkoutPlan, DistanceGoal, Distance } from "@bibixx/workoutkit";
import { saveWorkoutPlan } from "@bibixx/workoutkit/fs";

const plan = new WorkoutPlan({ referenceId: crypto.randomUUID() });
plan.asGoal({
  activity: "running",
  location: "outdoor",
  goal: new DistanceGoal(new Distance(8, "kilometers")),
});

await saveWorkoutPlan(plan, "./easy-run.workout");

No code at all: build the workout in the Workout app on your iPhone or watch, tap Share Workout, and the shared file is a ready-to-host .workout file.

2. Write the manifest next to it

Save this as index.json, with a date in the near future so you'll see it appear:

{
  "version": 1,
  "workouts": [
    {
      "date": "2026-08-12T07:00:00",
      "url": "easy-run.workout",
      "title": "Easy run — 8 km"
    }
  ]
}

3. Host both files

On GitHub Pages:

  1. Create a new public repository, e.g. my-workouts, and upload index.json and easy-run.workout.
  2. In the repo: Settings → Pages → Source: Deploy from a branch, pick main and / (root).
  3. A minute later your feed is live at https://<username>.github.io/my-workouts/.

Or, for a one-liner on your own machine: npx serve . and use http://<your-computers-ip>:3000/ from a phone on the same network. Netlify drop, S3, or any web server work the same way.

4. Connect the app

Paste the URL into Feed URL, leave Authorization empty, tap Connect. The workout appears in the list, downloads, and lands on your watch's Workout app.

The manifest, in full

A GET on your Feed URL must return JSON of this shape — here with every field present:

{
  "version": 1,
  "workouts": [
    {
      "id": "easy-8k-2026-07-27",
      "date": "2026-07-27T07:00:00",
      "url": "w/easy-8k.workout",
      "type": "workout",
      "title": "Easy — 8 km"
    }
  ]
}
FieldRequiredMeaning
versionno Set it to 1. Reserved for future contract changes; the app currently accepts manifests without it.
workoutsyes The list of planned workouts. An empty list is valid — it clears everything the app scheduled.
dateyes When to schedule it, in local wall-clock time on the phone: 2026-07-27 or 2026-07-27T07:00:00. Date-only defaults to 07:00. No timezone suffixes — 7 AM means 7 AM wherever you are.
urlyes The workout file — relative to the manifest (recommended, keeps the feed portable) or absolute.
typeno "workout" = Apple WorkoutKit binary. Missing → inferred from the .workout extension. Unknown types are silently skipped — the forward-compatibility door for e.g. .fit.
id, titleno Identification and the label shown in the app's list.
  • Trailing slash: a Feed URL ending in / gets index.json appended — https://x.com/feed/ and https://x.com/feed/index.json are the same feed.
  • Content type doesn't matter: the app parses the response body as JSON regardless of headers, and the URL doesn't have to end in .json.

Making .workout files

.workout is Apple's binary format for planned workouts (WorkoutKit's WorkoutPlan). Three ways to produce one:

Share from the Workout app

Build the workout on your iPhone or watch and tap Share Workout — the shared file is a .workout file, ready to host as-is.

@bibixx/workoutkit (TypeScript)

Full programmatic control — intervals, goals, and alerts. An interval session, for example:

import { WorkoutPlan, Step, Distance, Duration, DistanceGoal, TimeGoal } from "@bibixx/workoutkit";
import { saveWorkoutPlan } from "@bibixx/workoutkit/fs";

const plan = new WorkoutPlan({ referenceId: crypto.randomUUID() });
const custom = plan.asCustom({
  activity: "running",
  location: "outdoor",
  displayName: "Tempo intervals",
});

// 5-minute warmup
custom.warmup = new Step(new TimeGoal(new Duration(5, "minutes")));

// 4× (1 km work + 2 min recovery)
const block = custom.addBlock(4);
block.addStep("work", new DistanceGoal(new Distance(1, "kilometers")));
block.addStep("recovery", new TimeGoal(new Duration(2, "minutes")));

// 5-minute cooldown
custom.cooldown = new Step(new TimeGoal(new Duration(5, "minutes")));

await saveWorkoutPlan(plan, "./tempo-intervals.workout");

See the package README for pacer and triathlon variants, heart-rate/power/pace alerts, and JSON interop.

Swift, with Apple's WorkoutKit

If you'd rather stay in the Apple ecosystem: build a WorkoutKit WorkoutPlan and export it — a .workout file is exactly what WorkoutKit produces when a plan is shared.

Hosting options

  • GitHub Pages — free, HTTPS, zero maintenance; the quick-start path.
  • S3 / R2 / Netlify / Vercel — drop the folder in a bucket or a drag-and-drop deploy; the feed URL is the manifest's public URL.
  • Your own server — nginx, Caddy, anything: two static routes and you're done.
  • A dynamic server — the manifest doesn't have to be a literal file. Anything that answers GET with the JSON works. That's how trenuj.se does it: it serves the contract live at /api/watch/index.json, authenticated by a long-lived watch token.

Protecting a private feed

The app has exactly one auth knob: the Authorization field. Whatever you type there is sent verbatim as the Authorization header on every feed request.

You include the scheme yourself. If your server expects a bearer token, enter Bearer abc123 — not just abc123. Forgetting the Bearer  prefix is the most common setup mistake.

  • The header is sent only to the manifest's own host and port — never to a third-party host that an absolute workout url might point at. If your .workout files live elsewhere, that host must be publicly readable.
  • The value is stored in the iOS Keychain on your phone.
  • Server-side, check the header however you like: a reverse-proxy token check, basic auth, or long-lived per-device tokens like trenuj.se's watch tokens.
  • Public feed? Leave the field empty.

How syncing behaves

  • No caching. The app fetches the manifest fresh every time — an edit on your host is picked up on the very next sync.
  • When it syncs: on app launch (throttled to once per 30 minutes), on pull-to-refresh (instant), and via iOS background refresh (best-effort; iOS decides the actual timing). The foreground check interval is configurable in Settings.
  • Identity is url + date. Unchanged entries are left alone — completion state on the watch is preserved. Change either field and the entry is replaced.
  • Safe pruning. Entries removed from the feed are removed from the watch — but only on a clean pass. If any file failed to download, nothing is deleted, so a flaky network can't wipe your schedule.
  • Empty feed = clear. Publishing "workouts": [] removes everything the app scheduled.

Troubleshooting

Each entry below quotes the message the app actually shows.

“…” isn't a valid URL.

The Feed URL must start with http:// or https:// and include a host name.

The feed returned HTTP 401 for index.json — …

(Or 403.) The host wants authentication. Fill in the Authorization field — and remember to include the scheme (Bearer …) yourself. Whatever your server put in the response body is echoed after the dash, so your server can leave a hint there.

The feed returned HTTP 404 for index.json

Wrong path. Open the URL in Safari — you should see raw JSON. Remember the trailing-slash rule: …/feed/ means …/feed/index.json.

Couldn't load index.json — couldn't find the server …

DNS failure: a typo in the host, or a LAN-only hostname while you're on cellular.

Couldn't load index.json — couldn't connect to …

The server is down or the port is wrong. For LAN development, confirm the phone and the server share a network and that the server listens on 0.0.0.0, not 127.0.0.1.

This doesn't look like a workout feed (missing or malformed “workouts” list).

The URL returned something other than the manifest — an HTML page, a login redirect, invalid JSON, or a misspelled workouts key. Open it in Safari or run it through a JSON validator.

not a valid .workout file

Shown on a single row: the file at that workout's url isn't a WorkoutKit binary — often an HTML 404 page served with status 200, or a text file. curl -sI <url> and check what actually comes back.

A workout from the feed never appears in the app

Its type is unknown (e.g. .fit — not supported yet) and it was skipped, or its date is in the past. The Debug screen — Settings → tap Version five times — shows skipped items and the raw manifest.

Rows say “on watch” but the watch shows nothing

Give the pair a moment — the phone hands workouts to the watch over its own sync channel. Check the Watch app's connectivity if it persists.

FAQ

What time is a date-only workout scheduled?
07:00, local time.
How are timezones handled?
They aren't — deliberately. Dates are wall-clock time on the phone: 2026-07-27T07:00:00 is 7 AM wherever you wake up.
Can I serve .fit files?
Not yet. Set type on those entries and they'll be skipped cleanly today and picked up when support lands.
Can I use multiple feeds?
Not yet — it's on the roadmap. One feed per phone for now.
If I delete a workout from the feed, does it leave the watch?
Yes, on the next clean sync — see how syncing behaves.
Does the app phone home?
No. It only ever talks to the URL you configure.
